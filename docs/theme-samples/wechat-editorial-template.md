# 文章标题：把一个观点写成一张有呼吸的版面

_副标题可以轻一点：说明本文的观察对象、判断角度，或者给读者一个进入文章的理由。_

> 一篇公众号文章的设计感，不一定来自复杂 CSS。很多时候，它来自内容本身的编排：哪里停顿，哪里强调，哪里把资料拿出来单独看。

本文想讨论一个很小的判断：**当 Markdown 元素被当成编辑工具，而不是排版装饰时，文章会更像一篇真正的专栏。** 这也是 Cooper 主题最适合发挥的地方。主题负责稳定的文字灰度，内容负责制造层次。

在正式展开之前，先给读者一个简短的阅读地图：

- **主线一：** 为什么普通正文需要先建立信任。
- **主线二：** 怎样用 Markdown 元素制造版面节奏。
- **主线三：** 哪些元素适合放大，哪些元素应该克制。

---

## 一、开场先给一个清楚的判断

公众号文章的第一屏，最怕像一段还没有编辑过的草稿：所有句子都一样重，所有段落都只是往下排，读者不知道哪里是重点，也不知道作者到底想把他带到哪里。

比较好的开场，通常会在前两三段内完成三件事：提出问题、给出判断、建立语气。这里可以用 **粗体** 做主判断，用 ==高亮== 标出关键词，用 ++下划线++ 留下一个轻微的编辑标记。它们不需要同时出现很多次，但第一次出现时应该有意义。

例如这句话可以作为全文的中心句：**排版不是给内容套外壳，而是把内容里真正有层次的部分显露出来。**

> [!NOTE] 编辑台口径
> 第一屏尽量少用装饰。先让读者知道这篇文章值得读，再让版面慢慢长出层次。

### 一个可以复用的开场公式

你可以把开场写成下面这个顺序：

1. 一个具体场景：读者能立刻想象出来。
2. 一个反常识判断：让文章有继续读的理由。
3. 一句主张：用 **粗体** 固定全文的中心。

| 开场位置 | 内容任务     | 适合的 Markdown 元素 |
| -------- | ------------ | -------------------- |
| 第一段   | 进入场景     | 普通段落             |
| 第二段   | 提出冲突     | `==高亮==`           |
| 第三段   | 固定主张     | `**粗体**`           |
| 段末     | 给出阅读路径 | 列表或引用           |

## 二、把“装饰”变成编辑结构

真正有用的装饰，应该能回答一个问题：**它帮读者更快理解了什么？** 如果答案只是“看起来更丰富”，那它很快会变成噪音。

下面这个结构图适合放在文章前半段，用来说明全文逻辑。它不是为了炫技，而是帮读者在一眼内看到论述路径。

```mermaid
graph LR
  A[观察一个现象] --> B[提出一个判断]
  B --> C[拆成三个层次]
  C --> D[给出案例]
  D --> E[收束成行动建议]
```

流程图之后，要立刻回到正文。图表只是路标，不能替代论述。这里可以补一句：如果一张图不能让下一段更容易读，那它就不该出现。

### 小标题可以当作段内转向

四级标题适合承接一个小转向。它不像二级标题那样开启新章节，也不像三级标题那样建立一个稳定小节。它更像编辑在段落之间轻轻按下的一个停顿。

这时候可以加入一段被拎出来的旁白：

> 好的版面不必一直出声。它只需要在读者快要失去方向的时候，给出一次准确的提示。

如果有一个概念需要被特别记住，可以用注音或术语标记制造一点文字肌理。例如：[行间]{xíng jiān} 不只是行与行之间的距离，它决定了中文正文的整体呼吸。

## 三、用信息图承载“编辑整理过”的材料

当文章里出现三个以上并列信息时，不一定要继续写成段落。可以把它们整理成信息图，让读者先获得结构，再回到正文理解细节。

```infographic
infographic list-row-horizontal-icon-arrow
data
  title 内容层装饰的四种作用
  desc 让 Markdown 元素承担编辑功能，而不是纯视觉装饰
  items
    - label 重音
      value 1
      desc 用粗体、高亮固定文章判断
      icon edit
    - label 旁白
      value 2
      desc 用引用和 alert 区分主声部与补充声部
      icon quote
    - label 路径
      value 3
      desc 用流程图展示论述推进
      icon route
    - label 资料
      value 4
      desc 用表格、图注、脚注承载证据
      icon database
```

> [!IMPORTANT] 使用原则
> 信息图只适合表达并列、递进或流程。不要把普通段落强行塞进去，否则它会像一个漂亮但多余的组件。

信息图之后最好补一段解释，避免读者只看图不看文。这里可以把四个关键词重新拉回正文：**重音负责判断，旁白负责语气，路径负责结构，资料负责可信度。**

## 四、资料段落要像编辑整理过

公众号里的资料不一定只能堆链接。更好的做法，是把来源、判断、限制条件放在同一组结构里，让读者知道你不是随手引用。

::: remark 资料使用方式
如果文章需要引用报告、播客、访谈或网页，不要只放一个链接。先用一句话说明它为什么重要，再把链接放在正文或脚注里。
:::

下面是一个可以复用的资料对照表：

| 材料类型 | 不建议的写法 | 更适合的写法              |
| -------- | ------------ | ------------------------- |
| 引用句   | 大段复制     | 摘出一句，正文解释        |
| 数据     | 只放数字     | 说明口径、时间、限制      |
| 图片     | 只当配图     | 图片下方补一句编辑图注    |
| 链接     | 直接裸链     | 放进语境，必要时做脚注    |
| 术语     | 反复解释     | 第一次出现时用 `行内代码` |

## 五、结尾不要突然变成口号

文章结尾适合回到最初的问题，但不要把所有内容重新复述一遍。更好的方式，是给读者留下一个可执行的判断标准。

可以这样收束：

> 当你下一次编辑公众号文章时，不妨先不要打开 CSS。先看正文里有没有可以被提炼出来的结构：一句中心判断、一段旁白、一个流程、一组资料、一个注释。
> 如果这些东西本来就在内容里，Markdown 就足够让它们站出来。

最后给出一个简短清单：

- 中心判断是否只出现了一次，并且足够清楚？
- 高亮、下划线、波浪线是否都有具体含义，而不是随机强调？
- 引用和 alert 是否区分了“文学旁白”和“编辑提示”？
- 表格、流程图、信息图是否真的减少了理解成本？
- 图注和脚注是否补充了正文，而不是重复正文？

**一句话结论：好的公众号排版，不是把每一段做得更花，而是让内容里已经存在的层次被读者看见。**[^1]

[^1]: 这里的“出版物感”不是指纸质杂志的复古样式，而是指编辑秩序、文字灰度、资料组织和阅读节奏共同形成的可信感。
